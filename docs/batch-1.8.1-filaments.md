# Batch 1.8.1 — Filaments and catalog previews

Release base `6768b520b6698a75746275bd2c12dc921d2d503f` on feature branch `feat/batch-1.8.1-filaments`.

## Directory and requirements

- The directory uses stable `Filament.id` values. Manufacturer, series, material and color form a case-insensitive unique identity. The directory suggests existing labels, reuses their spelling and normalizes HEX values. Availability is an editable status. Retire a filament by marking it unavailable so existing groups keep their references. The admin UI and runtime role provide no filament deletion operation, and the foreign key restricts deletion when referenced.
- A `ProductVariant` owns ordered `VariantFilamentGroup` rows. Each group joins to filaments through `VariantFilamentAlternative`, with a composite primary key preventing duplicates and an inverse index on filament ID. Deferred database checks require each persisted group to contain at least one alternative. Replacing a variant's groups is atomic, and concurrent edits to the same variant use the product lock and an editor snapshot.
- Open a saved variant from **Variant filament requirements** on the product edit page. Copy requirements from another saved variant on the same product, then edit and save. Copies are independent. Merchant product and variant switches stay separate from manufacturing availability. The editor identifies unsatisfied groups and shows each filament's manufacturer, series, material, color and status.
- Catalog, product detail and cart query only the unsatisfied groups for each variant. One available alternative satisfies a group. Every group must be satisfied, and a variant with no groups passes by default. Existing merchant switches, variant identity, option selection, retirement and price rules still apply. Public configuration contains effective availability only. Sorted catalog prices use the same rule in SQL before pagination.
- Add-to-cart validates a native selection and its price with the authoritative cart lookup. Checkout locks product rows in ID order, which coordinates with the Batch 1.8 product configuration writers and requirement edits. It then takes shared locks on referenced filament rows in ID order and reads current availability within the order transaction. Directory updates serialize with checkout at that row lock. The transaction flushes deferred constraints before returning. Previously accepted online attempts continue to replay their immutable order snapshots. Cart and checkout reserve no filament.

## Catalog previews

The previous mobile selector chose one eligible card globally. Equal vertical distances left the first registered card playing when both cards in a row had GIFs. The selector reproduced this with two equally visible fixtures regardless of static image count.

A shared observer now lets each eligible preview play independently once at least 60% of its visual area is visible. Mobile users can pause or resume each animated preview. Playback still respects reduced motion, hidden tabs, data saver and slow connections. The primary photo link remains a direct tap target. Horizontal swipes suppress pointer navigation, and gallery arrows and animation controls use separate buttons. Desktop hover and keyboard focus previews retain their existing behavior. Catalog arrows use 24 px mobile and 32 px desktop faces, 16 px chevrons and 44 × 44 px buttons. The detailed gallery and lightbox keep their existing controls.

3. For rollback, first switch to application code that does not read the new tables. SQL contraction is permitted only with an empty directory and no requirements. If records exist, keep the additive tables and prefer forward recovery. Before reverting to an application version that ignores filament requirements, place affected products or checkout on hold through an approved operator procedure. Resume sales after requirement enforcement is restored or manufacturing availability is otherwise verified. Verify effective Production privileges and the schema as part of the operator rollout.

## Future extension points

Purchase batches and physical spools can reference the same filament ID while retaining each acquisition's date, supplier, price, purchased weight and remaining weight. Future consumption records can associate grams with a variant's requirement groups, preserving different quantities for each size. Allocation and consumption history can support FIFO and other costing methods. Group edits currently replace rows, so a future consumption model should explicitly preserve or version group identities before attaching historical consumption to them.

Estimated and actual manufacturing costs can combine material allocations with electricity, printer depreciation, packaging and other components. A separate pricing policy can default to MANUAL at the store level, with product overrides and more specific variant overrides. MANUAL keeps the selling price under administrator control and can surface a recommended price. AUTO may apply a recommendation after markup or margin, rounding, configured absolute or percentage repricing thresholds, and any required administrator approval. An administrator can lock a selling price with a manual override. Record policy inputs, approved changes and price history independently of costing. Historical order price snapshots remain immutable in both modes.
