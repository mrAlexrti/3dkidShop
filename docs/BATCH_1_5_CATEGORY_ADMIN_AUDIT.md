Audited 2026-11-12 on `batch-1-5-catalog-admin-audit`. This is a code audit, with read-only storefront HTTP checks. No category actions, maintenance jobs, seed, or DB mutations were executed. **No recommendations in this document have been implemented.**

## Minimal recommended plan — approval required

1. Add friendly slug validation and a localized collision error while retaining the DB unique constraint as the concurrency boundary. Decide canonical case and allowed slug characters before changing existing records; do not rewrite current slugs automatically.
2. Show order and child/product counts in the list. Explain why a category cannot be deleted before submission; keep server guards and confirmation. Clarify that renaming a slug invalidates old bookmarks.
3. Pass both names to Admin parent/product selectors and use `getCategoryName`. Add associated labels and specific localized validation errors.
4. If direct reorder is desired, add sibling-scoped move-up/down controls, one authorized transactional action, and deterministic tie handling. Reuse existing `order`; no schema change is necessary.
5. Review and retire/consolidate the conflicting seed and maintenance taxonomies, retaining documented read-only modes and strong environment checks. Never execute cleanup as part of ordinary UI work.

Do not add bulk deletion, automatic product reassignment, category alias history, arbitrary nesting, or a new category schema for this batch. Those need a separate decision if required.
