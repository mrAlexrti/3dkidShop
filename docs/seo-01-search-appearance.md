## Assets and Site Content

The supplied `3dkid-favicon.png` was cropped to a square around the artwork, with transparent outer corners. The pink circle, cream lettering and sparkles were preserved. The release includes PNGs at 16, 32, 48 and 96 px, a four-frame `/favicon.ico`, and a 180 px `/apple-touch-icon.png`. The preferred search icon is the stable `/favicon-96.png`. The separate `/seo/brand-mark.png` is the 256 px structured-data logo. `/seo/store-share.jpg` is the 1200 × 630 fallback social card built from the approved mark. The old autogenerated Next icon declarations were removed. [Google favicon guidance](https://developers.google.com/search/docs/appearance/favicon-in-search)

To reproduce the assets, pass the approved source file to `node scripts/generate-favicons.mjs "<approved-source.png>"`. The source SHA-256 was `2323fd454c1d3488b00f4041a0da5a0b080678114f94abc76aab4f0e5b8d5a31`.

**Admin → Site Content → SEO** supports UA and EN homepage titles and descriptions, website display name, and one primary HTTPS social image. The editor includes localized suggestions and counters, a locale-selectable approximate Google preview, upload, replacement and reset. Blank settings use the defaults. The preview explicitly says that actual Google results may differ. The existing authenticated save path, media validation, Blob uploader and cache invalidation are reused.

The favicon is displayed in the editor and versioned with code. A dynamic favicon is deferred because the general media uploader does not enforce a square icon, generate native icon sizes, or maintain a stable first-party icon URL for arbitrary uploads. No migration, external dependency or new environment variable is required.

## Indexing and legacy URLs

- Indexable pages declare HTTPS www canonicals. A category keeps its actual `category` slug and ordinary catalog pagination keeps its own page URL. Sort and search variants are noindexed with the clean catalog or category canonical. Campaign parameters do not enter canonicals. Empty categories are crawlable with `noindex` and stay out of the sitemap.
- The current locale is cookie-based. Server HTML, descriptions and social metadata are localized on the existing URLs. Ukrainian is the anonymous default. There are no separate crawlable language URLs and no hreflang declarations. A future locale routing project can add approved stable English paths with self-canonicals and reciprocal alternates.
- The sitemap queries current active records. Product last-modified dates use the stored `updatedAt` value. Static pages and category revisions have no fabricated last-modified date. Private checkout, account, admin, login, cart and API routes stay out of the sitemap. Private page routes carry noindex headers and keep their own access controls. Robots excludes admin and API crawling and permits public image and favicon requests.
- A unique case-only match redirects permanently to the stored product or category URL. Unicode product slugs are encoded for crawl URLs and decoded during lookup. Unknown category or product URLs return HTTP 404. Existing data does not establish a replacement for the old stickers or shopper URLs. Check the exact indexed shopper URL in Search Console, since `/product/shopper` was a candidate tested during the audit. No unrelated redirects were added.
- The product JSON-LD uses the localized catalog description and visible images. Offers use recorded prices and UAH. Variant groups use current size/color configuration and material availability. Retired variants are omitted and blocked variants do not advertise an unshown price. There are no generated ratings, GTINs, merchant policies or discounts. Variants share the existing product page, so independent variant landing-page eligibility is outside this release. Validate supported enhancements after deployment. [Google product variant guidance](https://developers.google.com/search/docs/appearance/structured-data/product-variants)

Metadata and page bodies share request-scoped reads, with the existing product availability resolver and media filtering. The sitemap uses fresh data to prevent archived products from persisting in index output. Metadata resolves before streaming the initial document. The catalog and product route-level skeleton boundaries were removed because they caused HTTP 200 responses for missing pages. Other loading boundaries stay in place. This trades early skeleton paint on those two routes for reliable HTTP status and head metadata.
